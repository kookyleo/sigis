# Sigis 存储方案

> 状态：设计阶段。本文描述目标与边界，不代表当前测试服务已经实现集群、HSM、任务或自动清理。

## 目标和边界

Sigis 使用内嵌 SQLite + Hiqlite Raft 维护任务元数据，每个节点使用本地文件系统保存自己负责的 PDF。单节点可以独立运行；集群采用固定三个完整投票节点。无需外部数据库、缓存或对象存储服务。审计外发服务可选；私钥由 HSM 保管，不写入 SQLite 或文件系统。

SQLite + Raft 存储层参考 a1 的结构，基于 Apache-2.0 许可的 Hiqlite 实现 Sigis 所需接口。Sigis 统一使用 Apache-2.0；不能将 a1 当前 MPL-2.0 源码直接改标为 Apache-2.0。依赖及来源在引入时逐项核验。

身份认证依赖上游 OIDC IdP；B-LT 所需的 TSA 和吊销信息由可配置的信任服务或调用方提供。这些是身份及验证服务，不是外部存储；当前测试服务尚未接入它们。

## 数据和路由

| 数据 | 位置 | 生命周期 |
| --- | --- | --- |
| 任务状态、节点 ID、文件标识与哈希、过期时间 | SQLite + Raft | 任务完成、拒绝或过期后，按配置保留并清理 |
| 一次性 Token 消费标记、幂等记录 | SQLite + Raft | 覆盖 Token 有效期及允许的时钟偏差，幂等记录覆盖约定的重试窗口 |
| 待发送 Webhook 及投递状态 | SQLite + Raft | 投递成功或达到明确的重试终止条件后按策略清理 |
| PDF 原文、签署结果及中间版本 | 任务所属节点的本地文件系统 | 任务有效期内保留；终态后按交付和保留策略清理 |
| 证书信任根、HSM 标识、TSA 与保留策略 | 各节点一致的部署配置或 Raft 元数据 | 运行配置，由运维管理，不能按任务 TTL 清理 |
| 审计记录 | SQLite + Raft；外部审计服务可选 | 按审计保留及导出策略处理，不视为普通缓存 |

公开入口可由负载均衡转发到任一健康节点。接收节点根据共享任务元数据，优先在所属节点本机执行；若文件不在本机，经节点身份校验的内部通道转发至所属节点。客户端仅使用任务 ID，不指定内部地址或文件路径。下载和验证任务结果同样按文件所属节点路由。

同步直签可以在请求内处理并直接返回文件；若不创建可恢复任务，可以不持久化 PDF。需要托管页面或异步恢复时使用本地文件和复制元数据。PDF 内容和签名证据不因为任务元数据复制而被复制；长期验证材料应嵌入交付的 PDF，最终文件由上游负责保管。

## 写入、并发和恢复

1. 接收文件时写入所属节点的临时文件，计算并校验哈希；完成文件持久化后原子改名并持久化目录，再通过 Raft 提交文件标识、哈希、所属节点与任务就绪状态。上传失败或元数据提交失败时不能报告任务已就绪。
2. 消费一次性 Token、核对任务状态及领取执行权使用同一个复制事务。状态更新使用条件检查和递增版本，防止旧执行者覆盖新状态；读取授权及领取必须使用足够新的一致视图，不能依赖未确认的过期副本。
3. HSM／TSA 调用、网络请求与文件写入均在可重算的存储事务之外。签署完成后先持久化结果文件，再以条件事务提交结果哈希、版本、任务终态以及需要的通知记录。事务成功后才能报告已完成。
4. HSM 操作和 Raft 事务无法构成单个原子操作。遇到进程在外部签署后崩溃等情况，标记结果不确定并按幂等及恢复策略处理；不得声称签名调用恰好一次。Webhook 接收方按事件 ID 去重。
5. 启动和访问时核对任务与本机文件：有效元数据指向缺失文件时标记或返回文件不可用；没有有效元数据的临时文件及孤儿文件，在足够的安全宽限期后清理。不得让孤儿清理删除仍在写入或正在提交的文件。

本地 PDF 为单副本：进程重启且磁盘保留时可恢复；所属节点暂时不可用时返回可重试错误或保留等待，不能报告已完成；节点或磁盘永久丢失时提示上游重新上传或重新提交。已签署结果若是唯一副本，丢失后不能假装可恢复。需要节点故障后自动接管文件时，后续须另行设计节点间文件复制及持久化确认；当前不承诺 PDF 高可用。

## 清理与保留

使用带过期时间的记录和**按请求触发的有界惰性清理**，思路与 a1 的 Counter／Queue 清理一致。每次清理限制数量及工作量，空闲时不保证到期后立即物理删除；节点恢复时扫描本地待删除文件和孤儿文件，必要时借助低频运维触发清理。业务访问必须即时检查有效期，不能因为清理尚未运行而接受过期 Token 或访问过期任务。

集群通过条件事务决定记录进入过期／删除状态，清理操作可重试、可重复；清理与领取、签署或下载竞争时以提交的状态和版本为准。使用可信的时间来源，保留可配置时钟偏差余量，不能仅凭某个节点的异常时间提前删除防重放记录。到期、删除任务与本地删除文件是分步操作，节点离线时保留待清理状态，恢复后继续。

已消费 Token 的记录不能在 Token 仍可被接受时淘汰；幂等记录不能早于约定的重试窗口清理。未完成的待投递通知不能仅因任务完成而静默丢弃。签署结果在上游确认取得或配置的交付期限结束前保留；若期限结束仍未取得，按约定返回明确状态或通知。

Raft 日志、SQLite WAL、快照和备份可能保留已删除元数据的历史副本；文件系统删除也不等于介质物理擦除。日志压缩、快照轮换、备份有效期与本地文件清理应按同一数据保留政策配置。长期审计按策略另行留存或导出；若要求外发成功后才允许本地删除，应保留待导出状态并处理外部服务不可用。

## 部署与运维

- **单节点**：一个进程、一份本地存储；本机磁盘是故障边界。
- **三节点**：三个固定成员、各有持久磁盘；元数据由多数派确认。失去多数派时拒绝需要一致性的状态写入，不以本地过期状态继续消费 Token。
- 节点间通道、Raft 数据目录、HSM 访问和可信配置需妥善隔离；集群应配置认证加密通信。备份／恢复覆盖完整节点数据，不能只复制正在运行的 SQLite 文件。
- 先支持固定拓扑及离线运维，不要求在线成员变更。a1 当前不支持单节点直接扩为三节点，丢失节点数据目录后从空目录重新加入也未验证；Sigis 不能在设计阶段承诺这两种恢复方式。备份、恢复与替换节点流程须在实现时确定并测试。
- 从旧备份恢复可能丢失备份之后的 Token 消费记录；恢复流程必须使受影响的未过期 Token 失效或采用其他能防止重放的方案，同时明确任务和结果恢复边界。

## 第一阶段范围

先实现 SQLite + Raft 小数据事务、本地 PDF、任务所有权路由、按请求有界清理，以及单节点和固定三节点的离线运维。验证重点是 Token 并发消费、所属节点离线、进程在文件／元数据提交之间崩溃、HSM 结果不确定、节点恢复清理和超期重试。具体库能力、性能和互操作性以实现与故障测试为准。
