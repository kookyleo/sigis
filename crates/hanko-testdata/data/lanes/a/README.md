# Lane A fixtures

Generated by lane A (certificates and CMS). Every file here is reproducible
from a committed script; nothing here contains private keys.

## `harvest/`

Validation calls recorded from the upstream pyHanko 0.38.1 test suites, by
`crates/hanko-cms/oracle/harvest.sh` (pytest plugin
`crates/hanko-cms/oracle/harvest_plugin.py`). The plugin runs the upstream
tests unchanged and records, for every call of
`async_validate_cms_signature`, `async_validate_detached_cms`,
`validate_sig_integrity`, `async_validate_pdf_signature`,
`extract_certs_for_validation` and `extract_signer_info`:

- the inputs: the CMS `SignedData` (DER, base64), the content or document
  digest, and the validation context's settings (trust roots, other
  certificates, CRLs, OCSP responses, time of interest, revocation and
  algorithm policies);
- pyHanko's outcome: the status fields, or the exception class, message and
  AdES sub-indication.

Certificates are stored once per file under `certs`, keyed by a SHA-256
prefix. The signatures were produced by pyHanko's own signers with the
Certomancer test PKI of `pyhanko/crypto/certomancer.yml` (public test keys).

Times: the upstream tests pin time with `freezegun` (mostly
`2020-11-01T00:00:00Z`); the recorded contexts carry the exact time of
interest, so the replay does not depend on the current date. Signatures with
ECDSA keys differ between harvests (random nonces); the replay compares
outcomes, not bytes.
